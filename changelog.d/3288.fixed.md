A capability's stored failure reason no longer repeats a credential when two credential flags sit next to each other: `--api-key --api-key sk-live-…`, `--api-key --token sk-live-…` and `--api-key --token=sk-live-…` now read the second flag on its own terms, so the literal behind it is masked with `[hidden]` before the stored reason is cut at 300 characters, instead of the flag name being taken as the first flag's value and the literal left in the sentence every turn. The accepted text cost is unchanged where no credential flag follows: `--api-key --verbose` still stores `--api-key [hidden]`, and a `command` or `args` token that is one bare word is still not read as a literal ([#3288](https://github.com/ThinkFlowLab/FlyBot/issues/3288)).
