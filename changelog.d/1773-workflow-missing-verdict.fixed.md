A Workflow step that ends without printing a declared `OUTPUT` its next gate reads now fails the step and the run instead of closing as `✓ 完成`: the downstream branch is held rather than skipped, and the run record names the step and the missing contract (`Missing OUTPUT verdict`), so "upstream emitted nothing" is no longer indistinguishable from "upstream emitted a non-PASS verdict" ([#1773](https://github.com/ThinkFlowLab/FlyBot/issues/1773)).
