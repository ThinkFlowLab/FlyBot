`node scripts/lint-plugins.mjs` — and with it `npm run verify` and the windows-latest leg of the compatibility workflow — now runs on Windows: the pack-and-import step handed GNU tar the tarball path and its `-C` destination as the full `C:\…` path, and tar reads the `C:` of a path that has a colon before its first slash as a remote `host:path`, so every plugin's pack step died with `tar (child): Cannot connect to C: resolve failed` and the four plugin suites never started there. The archive now goes in as a bare name resolved against the child's working directory, and the destination is that `cwd` instead of `-C`, so no tar argument carries a drive path — the shape is safe for the bsdtar Windows ships as well, which does not know `--force-local` ([#3296](https://github.com/ThinkFlowLab/FlyBot/issues/3296)).
