A capability's stored failure reason no longer repeats a credential the user typed into the capability's own command or arguments, or under a header or environment name that promises one: a value after a credential-looking flag in a stdio server's `command`/`args` (the next token, the `--flag=value` form, or a `NAME=value` token), and the value of a header or environment name such as `sig`, `hmac` or `pass` — with `sig` and `pass` matched as whole segments, so `assign`, `compass` and `bypass` keep their values — is masked with `[hidden]` before the stored reason is cut at 300 characters, longest value first and a value under six characters left alone, so a failed server's own error line can no longer print that credential into the Bot's system prompt every turn ([#3278](https://github.com/ThinkFlowLab/FlyBot/issues/3278)).
