A Bot name whose **drawn** form is already taken is refused. `#2879` refused only a name that draws nothing at all; a name that draws something and also carries a character the screen does not draw still passed, so `Dev` plus a combining grapheme joiner (or a braille blank, or a Hangul filler) sat beside the existing `Dev`: both rows read `Dev` while the identity key stayed distinct, and `@Dev` could only ever reach one of them. `createBot` and `updateBot` now compare `drawnKey()` — `nameKey()` with those characters removed — beside `nameKey()`, from either side. A drawn form nobody holds is still a name, and nothing is stripped from the stored name ([#2935](https://github.com/ThinkFlowLab/FlyBot/issues/2935)).
