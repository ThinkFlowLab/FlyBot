A channel that keeps refusing a send no longer costs memory for the life of the process: the notifier remembered every permanently refused idempotency key and never dropped one, while the sent keys beside it were capped at 1 000. The refused keys now keep the same bound and drop the oldest first, so a deleted channel or a revoked bot stays a remembered failure without the table growing with every send. See [#2808](https://github.com/ThinkFlowLab/FlyBot/issues/2808).
