A decided meeting's row on a Project board no longer reports `decision file gone` for a file that is still there ([#2033](https://github.com/ThinkFlowLab/FlyBot/issues/2033)): the board lists only the newest 200 decision files ([#2021](https://github.com/ThinkFlowLab/FlyBot/issues/2021)), and the lookup behind a meeting's own file name was built from that cut list, so every decided meeting whose file fell off the oldest end claimed its file had been deleted — while the same read reported the full count. The lookup now falls back to the names this read actually saw in the folder, so a file past the cut is named and only a name the folder no longer holds reads as gone; the fallback takes names from that read, never from the filesystem, so `../outside.md` still yields no path.
