`read_group_chat` no longer counts a share-seq reservation as a line the room said: a mention that reserves a remote line number writes nothing to the room log, so reserving one after a five-line log used to read `Latest in "Ops" (newest 5 of 6, oldest first):` and grew one phantom line per mention; the header stays `Latest in "Ops" (oldest first):`, the number is still issued from the room's own counter so the next line written takes the one after it, and a second mention is never a redelivery of an earlier line. A room whose log really was trimmed still reports the lines the cap dropped. See [#2855](https://github.com/ThinkFlowLab/FlyBot/issues/2855).
