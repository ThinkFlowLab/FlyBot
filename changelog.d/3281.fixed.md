A capability's stored failure reason no longer repeats a credential typed into a command line saved in the capability's own `command`, or a credential value that begins with `-`: a `command` containing a space or a tab is read as a command line and its tokens go through the same rules as `args` — the token after a credential-looking flag, the `--flag=value` form and a `NAME=value` token are masked with `[hidden]` — and the token after a credential-looking flag is its value even when it begins with `-`, so `--api-key --verbose` stores `--api-key [hidden]` and a second `--api-key` is masked as a value too. A `command` that is one bare token without whitespace stays unmasked, because it cannot be told from a program name, the same limit as a bare `args` token; the stored reason is still one line of at most 300 characters with the mask applied before the cut, longest value first and a value under six characters left alone, so a failed server's own error line can no longer print that credential into the Bot's system prompt every turn ([#3281](https://github.com/ThinkFlowLab/FlyBot/issues/3281)).
