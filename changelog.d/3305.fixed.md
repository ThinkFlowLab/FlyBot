A diagnostics log line or report row that echoes a credential header now masks its value: `X-Pat`, `X-Github-Pat`, `X-Token`, `X-Auth`, `X-Cookie`, `X-Session`, `X-Credential`, `X-Key`, `X-Signature` and `X-Amz-Signature` went through unmasked, because the name list `cleanText` uses for the report and the downloaded log (`CREDENTIALS` in `core/src/host/diagnostics.js`) only knew `api[_-]?key`, `authorization`, `x-api-key`, `password` and `secret`, plus the whole-segment `sig`/`pass`/`hmac` that `#3291` added. A name with at least one `field-` segment whose last segment is a credential word is masked now, so a server that echoes the request headers into a 401 body no longer reaches the user's own report with `X-Token: <value>` intact while `x-api-key: <value>` beside it is hidden; `passwd` joins the bare names beside `password`, which is not a word in any language and so eats nothing. `X-Patch-Id`, `X-Path-Id`, `X-Request-Id`, `session-count`, `key-name`, `author`, `compass`, `bypass`, `assign` and `status` still read as written, and so do sentences like `auth: failed to connect`, because a bare name stays readable: masking `signature:` on its own would eat any sentence that starts with it, so `Signature:` is recorded as an accepted limit in `docs/subsystems/core-host.md` rather than forced ([#3305](https://github.com/ThinkFlowLab/FlyBot/issues/3305)).
