A read-only window's group settings in the details drawer now say so instead of drawing the live form: the drawer's read-only branch was written for a Bot only, so a group kept its name, notice, who-answers, folder, member, **Pin**, **Hide** and **Delete group** controls while every write it offered could only be refused with `bot/read-only` ([#2387](https://github.com/ThinkFlowLab/FlyBot/issues/2387)). The branch now reads the window lock rather than the Bot, so a group gets the host's own sentence in a `role="status"` line in place of `GroupSettingsForm` and a writable window keeps today's form unchanged.
