**Workflow steps get the time the work needs (#1580):** a live step used to be killed after ten minutes, and ten minutes is shorter than implementing or reviewing a change takes, so every step that did real work failed mid-flight and the run was lost. The deadline is now per workflow: `stepTimeoutMinutes`, an integer from 1 to 120, given when the workflow is created or through the new `workflow/step-timeout` call, with 45 minutes as the default. A value outside that range is refused when it is written instead of silently falling back, and the timeout message names the number that applied.
