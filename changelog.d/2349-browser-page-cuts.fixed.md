`read_browser` no longer splits a long page between the two halves of a character: a part used to end on a UTF-16 unit, so a cut that landed inside an emoji handed the model two parts that each carried U+FFFD and printed a continuation point inside the character as well. The hard cut and the plain-text part now end on a code-point boundary and a `from` that lands inside a pair moves back to that character's first half, so the two reads join back into the original page and no character is dropped between them ([#2349](https://github.com/ThinkFlowLab/FlyBot/issues/2349)).
