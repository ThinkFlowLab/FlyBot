A workflow file written by a newer FlyBot is no longer rewritten by an older one: the workspace store refuses to save over a definition whose `version` is higher than the one it writes and leaves it byte-identical, and lists it as a newer file instead of showing a definition that has lost fields it could not read. The workflow plugin does the same for `workflows.json` — `workflow/state` now answers `store-newer-version` with the version that wrote it, and every write is refused, so the owner's workflows, runs, claims and `seq` can no longer be replaced by the factory fixture ([#2681](https://github.com/ThinkFlowLab/FlyBot/issues/2681)).
