A memory or workflows folder is now read as empty, and refused as a write target, when it is a symlink ([#2057](https://github.com/ThinkFlowLab/FlyBot/issues/2057), [#2068](https://github.com/ThinkFlowLab/FlyBot/issues/2068)): one resolver walks every segment of `<home>/memory` — the root, `memory/bots`, the Bot's or team's own folder — and the same rule covers `snapshots`, `summaries`, `archive`, `reviewed.json` and `journal.jsonl`, plus a workspace's `workflows/`. Readers take only a real directory, so a link to a folder outside the home no longer feeds another folder's `MEMORY.md`, topics, prompt snapshot, summary or workflow definitions into a prompt, a listing or a page; a host write or delete still creates a folder that is not there yet, as before, and refuses a linked one instead of writing or deleting through it, and the entry writers behind `remember`, `edit` and `forget` refuse it the same way. A linked folder is named once per folder and process in one warning, because "nothing saved" and "nothing readable" look alike otherwise. A single `*.md`/`*.json` file that is a link is still read (unchanged), and a local process that can write inside the home can still win a redirect race.
