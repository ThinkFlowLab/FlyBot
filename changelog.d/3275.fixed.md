A capability's stored failure reason no longer repeats a credential the user typed into the capability itself: when a server echoes a request header or an environment value back in its own error body, the value of a name that promises a credential (`key`, `token`, `secret`, `auth`, `password`, `passwd`, `credential`, `signature`, `cookie`, `session`, `bearer`, and `pat` as a whole segment — `X-Github-Pat` yes, `X-Patch-Id` no) is masked before the reason is stored, longest value first so one credential is never left as a surviving tail, so it can no longer be printed into the Bot's system prompt every turn ([#3275](https://github.com/ThinkFlowLab/FlyBot/issues/3275)).
