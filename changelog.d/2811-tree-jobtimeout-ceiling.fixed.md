The tree plugin's `jobTimeoutMs` is capped at 2147483647 ms (about 24.8 days): a larger value — 30 days is the natural way to ask for "effectively no deadline" — was handed to Node's `setTimeout`, which silently replaced it with 1 ms, so every queued reorganization job was reported abandoned on a healthy host while the host call it was waiting for kept running and writing. The value is now clamped to the ceiling with one warning that names the deadline actually used, so a job whose host call answers inside it resolves normally. See [#2811](https://github.com/ThinkFlowLab/FlyBot/issues/2811).
