A file that another name also holds is no longer written through at its leaf: the decision log, the diagnostics log, the memory journal, and a workflow definition or project file that is hard-linked to a name outside the home are refused exactly like a symbolic link there — one warning, the other name keeps its bytes, the record is dropped or the save is refused — instead of the append or the truncate landing in the shared inode ([#2079](https://github.com/ThinkFlowLab/FlyBot/issues/2079), [#2114](https://github.com/ThinkFlowLab/FlyBot/issues/2114)). The leaf now asks the same `nlink === 1` rule the temporary name already used, so the two answers for one file cannot disagree; a file carrying one name is written as before, and a missing file is still created ([#2159](https://github.com/ThinkFlowLab/FlyBot/issues/2159)).
