`workflows/<id>.json` — the file a saved workflow definition lives in — was written with `writeFileSync`, which opens the target at zero bytes and then writes, so a second window reading inside that window parsed half a definition (or nothing), `list()` skipped it as unparsable and `open()` answered `workflow/not-found` for a definition that was not lost. Saving now stages a private temp name in the same folder and renames it over the target, for both `save()` and the `project.json` pointer `setDefault()` writes, so every read sees the previous complete definition or the new one, and a crash inside the write leaves the old bytes whole. A temp name a crashed write left behind is swept by the next write, a failed write removes its own temp name, and a link planted at the temp name is refused before the first byte. See [#2762](https://github.com/ThinkFlowLab/FlyBot/issues/2762).
