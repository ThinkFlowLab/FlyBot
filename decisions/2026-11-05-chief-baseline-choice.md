# Let Chief choose an existing successor baseline

Date: 2026-11-05. Accepted under the Owner continuation of #2483. Target:
delivery/ai-centric-development-service.

An inherited seed can make a reworked resource checkout older than current host
HEAD. Approved integration inputs mean available/required merged objects, not an
automatic checkout replacement. Give Chief the original continuation-state facts
and reuse the existing task.run continuation contract for an explicit Developer
route/return. Do not add a baseline state machine, timer, allocator or inferred
next role. Ordinary routing without a choice retains its existing semantics.

Use exact saved/current generation, workspace snapshot and latest HEAD fences.
Keep original Attempt history, draft lineage, PR ancestry and new evidence gates.
Admission excludes only its authenticated current Chief coordination; no old or
unknown worker is released. Separate input admission from successor selection to
avoid dropping or implicitly changing inputs.

Regression evidence uses actual disposable Git repositories and resource checkouts;
Docker transport is emulated in these baseline tests. This is not live deployment,
a real-model choice, paid inference or OpenToday acceptance.
